Package Starter Kit

Paste this preamble once. Almost every command below depends on one of these lines — if LaTeX says a command "doesn't exist" or "Undefined control sequence" during compilation, this table is the first place to check. LaTeX's core (called LaTeX2e) is deliberately minimal; nearly everything visually interesting — colored text, decent tables, real subfigures — lives in optional packages that you must explicitly load with \usepackage{} before \begin{document}.

preamble.tex 
\documentclass{article}

\usepackage[utf8]{inputenc}
\usepackage{amsmath, amssymb}     % cases, align, matrices, symbols
\usepackage{amsthm}               % theorem/lemma/proof environments
\usepackage{graphicx}             % \includegraphics
\usepackage{subcaption}           % subfigures
\usepackage{booktabs}             % \toprule \midrule \bottomrule
\usepackage{multirow}             % \multirow
\usepackage{float}                % the [H] "exactly here" placement
\usepackage[table]{xcolor}        % colors + \rowcolor, \cellcolor
\usepackage[normalem]{ulem}       % \sout strikethrough (keeps \emph italic)
\usepackage{enumitem}             % custom list labels/spacing
\usepackage{natbib}               % \citet / \citep author-year
\usepackage{hyperref}             % load LAST: \url, \href, colored refs

A few things worth understanding about this list rather than just memorizing it. First, order occasionally matters: hyperref redefines a lot of internal LaTeX machinery to make cross-references clickable, so loading anything after it (particularly amsmath-adjacent packages, or specialised clever-reference tools) risks silent conflicts — the safe habit is "hyperref goes last." Second, amsmath isn't optional scaffolding you can skip if you "don't need fancy math" — the cases, align, and \text{} constructs you'll use in nearly every assignment all come from it, and omitting it is the single most common reason a piecewise function refuses to compile. Third, [table] as an option to xcolor quietly also loads the colortbl package for you — if you ever see \rowcolor not being recognised, it usually means someone loaded plain xcolor without the table option.

If instead you see ! LaTeX Error: Environment cases undefined, that always means amsmath is missing.

Text Formatting

Both the C2 paper and your teacher's own main-old-version.tex stacked bold, italic, emphasis, and underline in one paragraph, then repeated the exercise with font sizes — treat both as a checklist you should be able to reproduce blind.

Weight, slant, emphasis, underline

LaTeX gives you four closely related but genuinely different commands here, and exam answers lose marks specifically for swapping them. \textbf{} changes the font weight to bold and nothing else. \textit{} changes the shape to italic and nothing else — it will not become upright again no matter what surrounds it. \emph{} is semantically different: it means "emphasize this," and LaTeX decides how to render that based on context. Inside normal upright text it renders as italic, exactly like \textit. But nest an \emph inside text that is already italicized (a theorem statement, another \emph, a quotation environment) and it flips back to upright, so the emphasis still stands out. \textit can never do that — it has no concept of "the surrounding context," it just always means italic.

source 
This sentence has \textbf{bold},
\textit{italic}, \emph{emphasized},
and \underline{underlined} text.

\textit{An italic sentence where
\emph{this part} flips back upright.}
rendered
This sentence has bold, italic, emphasized, and underlined text.
An italic sentence where this part flips back upright.
Common mistake: writing \underline{a very long sentence that needs to wrap across two lines}. Base LaTeX's \underline draws one continuous rule and does not know how to break at a line wrap — the underline will either overrun the margin or look broken. For anything longer than a few words, load \usepackage{soul} and use \ul{} instead, which underlines properly across line breaks.

Strikethrough (needs a package)

Base LaTeX has no strikethrough command at all — this is a deliberate gap, not an oversight, because "struck-through text" isn't something academic typesetting traditionally needed. You get it from the ulem package, loaded with the [normalem] option. That option matters more than it looks: ulem's whole reason for existing is to redefine how underlining works, and by default it also hijacks \emph to mean "underline the text" instead of "italicize it." Loading it plain will silently change the visual meaning of every \emph already in your document, which is a very confusing bug to track down because nothing throws an error — your emphasized words just stop looking emphasized the way you expect. [normalem] tells ulem to leave \emph alone and only give you the new commands (\sout, \uline, \uwave) without the side effect.

source 
% preamble: \usepackage[normalem]{ulem}
The old deadline was \sout{March 3}.
A wavy alternative: \uwave{read carefully}.
rendered
The old deadline was March 3. A wavy alternative: read carefully.

Color: text, highlight boxes, custom colors

\textcolor{name}{text} is the workhorse. LaTeX ships with a handful of built-in names (red, blue, green, yellow, cyan, magenta, black, white, gray) but for anything specific — a university brand color, a precise shade you were given — define it once with \definecolor{name}{model}{value} and reuse the name everywhere. The three common color models are RGB (three integers 0–255), rgb (three decimals 0–1), and HTML (a six-digit hex code, no leading #). Once defined, that name behaves exactly like a built-in color everywhere in the document — inside \textcolor, inside \colorbox, and later inside table cells too.

source 
\definecolor{buetblue}{HTML}{1B4F72}

\textcolor{red}{Warning text.}
\textcolor{buetblue}{Custom color text.}
\colorbox{yellow}{Highlighted text.}
\fcolorbox{black}{yellow}{Framed highlight.}
rendered
Warning text.
Custom color text.
Highlighted text.
Framed highlight.

This same \textcolor/\colorbox machinery is exactly what colors table cells later in §04 — one package, two use-cases, so learning the color-name syntax here pays off twice.

Font size & family

The ten size-switching commands form a strict, ordered ladder from smallest to largest: tiny → scriptsize → footnotesize → small → normalsize → large → Large → LARGE → huge → Huge. Notice the capitalization pattern isn't random — it climbs from all-lowercase, to one capital, to all-caps, roughly tracking size within each name (large < Large < LARGE, same for huge/Huge). These are declarations, not commands that take an argument — that's why you always see them wrapped in an extra pair of braces, {\Large some text}: the braces create a group, the declaration changes the size for everything inside that group, and the closing brace restores whatever size was active before. Forget the braces and the size change leaks into the rest of your document — every following paragraph stays huge until you manually switch back, which is a very common and very visible mistake in exam scripts.

source 
{\tiny tiny} {\small small} {\normalsize normal}
{\large large} {\Large Large} {\LARGE LARGE}
{\huge huge} {\Huge Huge}

\textrm{serif} \quad \textsf{sans-serif} \quad \texttt{monospace}
rendered
tiny small normal large Large LARGE huge Huge
serif   sans-serif   monospace
Common mistake, straight from the teacher's own file: \Large{Large Text} (braces placed after the size command, wrapping only the words) versus {\Large Large Text} (braces wrapping the whole declaration). Both usually look identical for a single word or short phrase, which is exactly why this mistake survives unnoticed — but \Large{...} is subtly wrong: \Large is not a command that takes {...} as an argument, so writing it that way works by accident (the braces just happen to form a group right after), not by design. The safe, unambiguous habit is always {\Large text} with the size switch as the very first token inside the group.
02

Lists & Labelling

The Image Synthesis paper mixed itemize and enumerate, used roman numerals, sub-bullets, and a bold inline "mini-header" item. Your teacher's own template independently used a dash bullet and a bold [Description] label on plain itemize, no extra package required. This section covers the full spread, from zero-package tricks to the fully customizable enumitem machinery.

The three base environments

LaTeX ships with exactly three list environments out of the box, and it helps to be explicit about what each one is for, not just what it looks like. itemize is for an unordered collection where sequence carries no meaning — swapping two bullets shouldn't change anything the reader understands. enumerate is for a sequence where order is the information — steps in a procedure, ranked items, anything you'd later refer back to as "step 3." description is for term–definition pairs, and is the one people forget exists, reaching instead for a bold word followed by itemize when description would be both shorter to write and more semantically correct.

Custom bullets and labels without any extra package

Before reaching for enumitem, know that base itemize already lets you override one item's marker by passing it in square brackets: \item[--] swaps the bullet for a dash just for that line, and \item[\textbf{Description}] replaces the bullet entirely with bold text — this is precisely the "mini-header" trick used in the Image Synthesis paper and in your teacher's own file. This is the right tool when you need to override one or two items; if you need to change the marker for an entire list consistently, that's what enumitem's label= option (below) is for.

source (from your teacher's file) 
\begin{itemize}
    \item first item
    \item [--] second item
    \item [\textbf{Description}] This is
      the description

    \begin{itemize}
        \item nested item 1
    \end{itemize}
\end{itemize}
rendered
  • first item
  • —  second item
  • Description  This is the description
    • nested item 1

Notice the nested itemize in the source sits outside the third \item's own line but still inside the outer itemize block — LaTeX doesn't require nested content to be glued to the exact \item line; it just needs to appear somewhere between that item and the next one (or the \end{itemize}) to render as a sub-list of the item above it.

Enumerate labelling variations (enumitem)

By default, enumerate numbers with plain Arabic numerals followed by a period: 1. 2. 3. Changing that globally — to roman numerals, letters, or a custom pattern — is what the enumitem package's label= option is for. The syntax takes some getting used to: you write the literal punctuation you want around the number, and drop in a placeholder token — \alph*, \Alph*, \roman*, \Roman*, or \arabic* — exactly where the counter itself should appear. The asterisk is not decorative; it's part of the required syntax and means "substitute the running counter value here."

source 
\begin{enumerate}[label=(\alph*)]
  \item divisible by 4
  \item divisible by 400
\end{enumerate}

\begin{enumerate}[label=\Roman*.]
  \item Primary Rays
  \item Secondary Rays
\end{enumerate}

\begin{enumerate}[label=\arabic*), start=3]
  \item continues from three
\end{enumerate}
rendered
(a) divisible by 4
(b) divisible by 400
I. Primary Rays
II. Secondary Rays
3) continues from three

Reference: \alph* = a,b,c  ·  \Alph* = A,B,C  ·  \roman* = i,ii,iii  ·  \Roman* = I,II,III  ·  \arabic* = 1,2,3.

Common mistake: nesting a plain enumerate inside another enumerate (as in your teacher's (i), (ii), (ii.a), (ii.b), (iii) example) without giving the inner list its own label=. LaTeX's default nesting behaviour auto-switches style by depth (1,2,3 → a,b,c → i,ii,iii → A,B,C), which is convenient until you've also set a custom label on the outer list — then the inner list often silently reuses the outer numbering style instead of stepping to the next default, and the roman numerals from the outer list and inner list become impossible to tell apart. If you've customized one level, customize the level below it explicitly too.

Nested / mixed lists + a bold "mini-header" item

\begin{itemize}

      \item Light Placement
    \end{itemize}

There's no special "mini-header" command — it's just a normal \item whose text starts with \textbf{}, followed by a nested itemize. Both this pattern and the teacher's \item[\textbf{Description}] pattern achieve visually similar results through genuinely different mechanisms — the first bolds part of the item's text, the second replaces the item's marker entirely. Either is correct; know which one you're doing.

Description lists & tight spacing

Default LaTeX lists are noticeably loose (extra vertical space between items) because that's the safest default for arbitrary content. noitemsep (kill the extra spacing between items while keeping spacing before/after the list) and topsep=2pt (shrink the gap before/after the whole list) are the two options you'll reach for constantly once you start caring about a document's visual density, e.g. fitting a long spec sheet on one slide or one exam page.

Document Structure & Navigation

Every past paper used a title block plus a numbered section hierarchy, and both of your teacher's templates layered on \tableofcontents, an unnumbered heading, and — in the older file — a full \listoftables too. This is the skeleton every one of your documents will share.

Title block

\title{The History Behind Leap Year}
\author{Your Name (Your Student ID)}
\date{\today}

\begin{document}
\maketitle

\title, \author, and \date only store the information — nothing is typeset until \maketitle is called inside the document body. \date{\today} inserts whatever the compile date is at build time, which is convenient but means the date silently changes every time you recompile — for a fixed submission date, write it literally instead: \date{June 2026}.

Section hierarchy

\section{History}
\subsection{Julian Calendar}
\subsubsection{Detail}
\paragraph{Aside.} inline run-in text

In the article class there is no \chapter — the top level is \section. \paragraph and \subparagraph exist but render as bold run-in text with no number by default (more on exactly why below) — they are easy to mistake for a bug rather than the intended, documented behaviour.

Why some headings get numbers and some don't — secnumdepth and tocdepth

This is one of the single most confusing things in LaTeX document structure, and it explains something you've almost certainly already seen: in your teacher's own template, \paragraph{Paragraph XYZ} gets no number at all, while every \subsubsection above it does. This isn't random — every sectioning command has a numeric "depth" baked in: \section is depth 1, \subsection is depth 2, \subsubsection is depth 3, \paragraph is depth 4, \subparagraph is depth 5. Two invisible counters then gate what actually happens to each one: secnumdepth controls the deepest level that gets a printed number, and tocdepth controls the deepest level that gets an entry in \tableofcontents. For the article class, both default to 3 — meaning sections, subsections, and subsubsections are numbered and appear in the TOC automatically, but paragraphs (depth 4) and subparagraphs (depth 5) get neither, by design, because a document with numbered paragraphs and a TOC entry for every one of them would be unreadable clutter. If you genuinely want numbered paragraphs, you raise the counters yourself:

\setcounter{secnumdepth}{4}   % now \paragraph gets a number
\setcounter{tocdepth}{4}      % ...and shows up in \tableofcontents too

Book and report classes default secnumdepth to 2 instead of 3 — meaning even \subsubsection is unnumbered by default in those classes, which surprises people coming from article. If a heading in a report-class document looks like it "should" have a number and doesn't, this is almost always why.

Unnumbered headings, and getting them into the TOC anyway

Every sectioning command has a starred variant — \section*, \subsection*, and so on — that suppresses both the number and the automatic TOC entry, regardless of what secnumdepth/tocdepth say. This is what your teacher's file used for \section*{Unlisted Section}, and it's the right tool whenever a heading is structural but shouldn't be numbered — "Abstract," "Acknowledgements," "References," "Disclaimer." The catch: because the starred version genuinely never touches the TOC machinery, it stays invisible in \tableofcontents even if you want it listed. The fix is to manually add a line to the table-of-contents file yourself, immediately after the heading:

\section*{Disclaimer}
\addcontentsline{toc}{section}{Disclaimer}

The three arguments to \addcontentsline are: which list file to write to (toc, or lof/lot for figures/tables), what level to format it as (section, subsection, ...), and the text to display.

The full "list of..." family, and why compiling twice isn't optional

Your teacher's older template calls all three list-generating commands back to back: \tableofcontents, \listoftables, and \listoffigures (all figures/tables need a \caption to appear in these — an uncaptioned figure is invisible to both lists). All three work identically under the hood and share the exact same quirk that trips up almost every new LaTeX user: on the very first compile, they will be wrong, empty, or missing entirely — not because anything is broken, but because of a fundamental chicken-and-egg problem. \tableofcontents needs to know the page number of every section, but sections later in the document haven't been typeset yet when LaTeX reaches the TOC near the top of the file. So instead, the first compile pass silently writes a side-file (.toc, .lot, .lof) recording everything it found, and only the second compile pass reads that file back in and actually typesets the correct list. This is why "just compile it twice" is not superstition — it's the literal mechanism.

Common mistake: adding a new section, recompiling once, and concluding the table of contents is "broken" because it's missing the new entry or shows stale page numbers. It isn't broken — it's one compile pass behind. Whenever you edit headings, figure captions, or table captions, run pdflatex twice before judging the result.

Forcing exact placement: [H] vs. the hints [h] [t] [b] [p]

Both your Tables (§04) and Figures (§05) sections already cover the standard placement letters — but it's worth being precise about what they actually promise, because the honest answer is: not much. [h] ("here") is only a suggestion. LaTeX runs an internal aesthetic algorithm that tries to avoid ugly page breaks and half-empty pages, and it is entirely willing to override your [h] and float the content to the top of the next page if fitting it exactly "here" would look bad by its own rules. This is why figures sometimes seem to "jump" a page or two away from where you placed them in the source — that's not a bug, that's LaTeX's placement algorithm doing exactly what it's designed to do.

Your teacher's older template sidesteps this entirely by loading \usepackage{float} and using [H] (capital H) instead, as in \begin{table}[H]. This is a genuinely different specifier, not a stronger version of the same one — [H] means "place this exactly at this point in the source, full stop, no aesthetic negotiation." The trade-off: because LaTeX is no longer allowed to move it, a large [H] figure can force an awkward page break or leave a large gap of white space, precisely the ugliness the normal float algorithm exists to prevent. Use [H] when exact positioning matters more than a clean layout (e.g. "this diagram must be right next to the paragraph describing it" for a grader); use the lowercase hints, ideally combined as [htbp], when you trust LaTeX's placement judgment and just want a reasonable result with minimal fuss.

Dummy text for testing a layout: lipsum

Your teacher's newer template fills every section with \lipsum[1-6]-style calls instead of real content — this is a completely standard, deliberate technique, not a placeholder someone forgot to remove. \usepackage{lipsum} gives you access to roughly 150 pre-written "Lorem ipsum" paragraphs, individually numbered, so you can build and check a document's visual structure — does this figure fit next to this paragraph? does this section run too short? — before the real writing exists. \lipsum alone inserts paragraph 1; \lipsum[5-7] inserts paragraphs 5 through 7 back to back; \lipsum[8] inserts just paragraph 8.

Practical use for you: when you're handed a mark-distribution sheet like your Online-1 papers (10 marks for lists, 25 for equations, ...) before you've written a word, scaffold the whole document with real headings and \lipsum filler first, get the tables/figures/equations exactly right, and only then replace the filler paragraphs with real prose. It separates "does the LaTeX work" from "is the writing good," which is a much easier way to debug either problem in isolation.

Page breaks: \newpage vs. \pagebreak

Your teacher's older template calls \pagebreak three times, right after \maketitle, before \tableofcontents, and before \listoftables. \newpage is the blunt, unconditional instrument: it ends the current page immediately, no matter what, and starts fresh. \pagebreak (optionally \pagebreak[0] through \pagebreak[4]) is a priority hint to the page-breaking algorithm, the same mechanism behind \linebreak for lines within a paragraph — [4] (the default when you write bare \pagebreak) means "strongly prefer breaking here," and in the overwhelming majority of real documents it does in fact force a break, but technically it is still a preference the algorithm is allowed to weigh against other constraints, unlike \newpage's absolute guarantee. For everyday use the two are close enough to interchangeable; reach for \newpage when you want a guarantee with zero ambiguity, which is most of the time.

Tables — multirow & multicolumn

This is exactly what the Leap Year paper's "Divisible By" spanning header, and the Document Structure paper's merged "Module B" row, were built from — and your teacher's older template independently drills the same three ideas (multicolumn, multirow, booktabs) as three separate, deliberately minimal subsections before combining them.

The mental model: rows, columns, and why & and \\ aren't optional

A tabular environment is, underneath the visual formatting, a strict grid. The column specification you give it — {l c r}, {|l|c|r|}, and so on — fixes the number of columns for the entire table before a single cell is written. Every row must then contain exactly that many cells, separated by &, and terminated by \\. Both symbols are easy to get subtly wrong in ways that produce genuinely unhelpful error messages: forgetting the final \\ on the last row (LaTeX will often still compile, just merging that row visually with whatever comes after the table) or writing one & too many or too few for the declared column count, which throws ! Extra alignment tab has been changed to \cr or Misplaced alignment tab character & — two of the most common error messages you'll hit while learning tables, and both are almost always a miscount of columns, not a deep problem.

\multicolumn — one header spanning several columns

\multicolumn{n}{align}{content} takes over for exactly n of the columns that row would otherwise need, re-declares their alignment just for this cell (it can differ from the table's own column spec — useful when a spanning header should be centered even though the columns underneath are left- or right-aligned), and prints content across the merged space. Crucially, because it consumes n columns' worth of &-separated slots in one go, the rest of that row still needs exactly the right total column count — a row with one \multicolumn{3}{...}{...} plus two ordinary cells is only using 5 "slots" of table width but is written with just 3 &-separated entries, and this is precisely where people miscount and trigger the alignment-tab errors above.

source 
\begin{tabular}{|c|c|c|c|c|}

\hline

\multicolumn{3}{c|}{...} reads as: span 3 columns, center-align, put a | vertical rule after. \cline{2-4} draws a horizontal rule under only columns 2–4, leaving the merged "Year"/"Leap Year?" cells uninterrupted. \multirow{2}{*}{Year} (from the multirow package) merges that cell down through 2 rows; the * as the width argument tells multirow to use the column's natural width rather than a fixed size you specify.

\multirow in isolation

The mirror-image situation to \multicolumn: a cell that should visually span two or more rows instead of columns. The catch that catches almost everyone the first time: when a cell above merges downward, the row(s) below it must have one fewer &-separated entry for that column, because the merged cell has already claimed that grid position — you do not write an empty placeholder cell for it.

source (from your teacher's file) 
\begin{tabular}{|c|c|c|}
    \hline
    c11 & c12 & c13 \\
    \hline
    \multirow{2}{*}{c23} & c22 & c23 \\
    \cline{2-3}
     & c32 & c33 \\
    \hline
\end{tabular}
rendered
c11c12c13
c23c22c23
c32c33

Look closely at the second-to-last row: it begins with a bare & — an intentionally empty first cell — precisely because the merged c23 cell above is already occupying that grid position for both rows. This is the exact detail people get wrong when adapting a multirow example: they either leave the cell genuinely empty (correct) or, more often, try to also write content there (which shifts every subsequent cell in that row one column to the right and throws off the whole table).

Booktabs style + colored rows/cells

booktabs is a small but opinionated package built entirely around a single typographic argument: hand-ruled tables with a full grid of vertical and horizontal lines look cluttered and amateurish in print, and professional publishing almost universally uses just three carefully-weighted horizontal rules — a slightly heavier rule at the very top (\toprule), a lighter rule separating the header from the body (\midrule), and a heavier rule at the very bottom (\bottomrule) — with no vertical lines at all. If this looks "incomplete" compared to a fully gridded table, that reaction is exactly what the package is trying to train out of you; it's the deliberate convention, not a missing feature.

source 
\begin{tabular}{lcc}
\toprule
Method & Accuracy & Time \\
\midrule
\rowcolor{gray!15} Rasterization & Medium & $O(n)$ \\
Ray Tracing & High & $O(n^2)$ \\
Hybrid & \cellcolor{yellow!40}High & $O(n^2)$ \\
\bottomrule
\end{tabular}

\rowcolor{} tints a whole row and must appear as the very first thing in that row, before any cell content; \cellcolor{} tints a single cell and is placed inside that cell like any other content. Both need \usepackage[table]{xcolor}. The gray!15 / yellow!40 syntax mixes a named color with white — yellow!40 means "40% yellow, 60% white," which is how you get pastel tints instead of a jarring saturated color sitting behind readable text.

Your teacher's file demonstrates one more booktabs-specific rule you won't find in plain \hline-based tables: \cmidrule, a partial-width version of \midrule that plays the same role \cline plays for grid-style tables, but drawn with booktabs' lighter weight and — critically — with automatic trimming so the rule doesn't visually collide with the vertical whitespace of a merged header above it:

\begin{tabular}{llr}
    \toprule

Positioning, captions, and column types

\begin{table}[htbp]
  \centering
  \begin{tabular}{l p{4cm} r}
    ...
  \end{tabular}
  \caption{Comparison of Image Synthesis Techniques}
  \label{tab:comparison}
\end{table}

[htbp] stacks placement hints in priority order: try here, else the top of a page, else the bottom, else give it its own page of just floats. Add ! (e.g. [h!]) to tell LaTeX to relax some of its internal aesthetic thresholds — not to override placement entirely (that's what the float package's [H], discussed in §03, is for), just to be less picky about what counts as "good enough" before accepting your preference.

Column types: l/c/r = fixed-width left/center/right (width determined by the widest cell content, no wrapping), p{width} = fixed-width paragraph column that wraps long text and top-aligns its content vertically, m{width}/b{width} (from the array package) = the same wrapping behaviour but middle/bottom-aligned instead. Leaving a cell empty (just & with nothing between) — like the missing method name in your Image Synthesis table — is perfectly valid syntax, not an error.

Common mistake: putting \label{} before \caption{} inside a table or figure. LaTeX assigns the actual number to a label by looking at whatever numbered counter was most recently updated — and it's \caption that updates the table/figure counter, not \begin{table} itself. A label placed above the caption captures whatever number was current before this table (often the previous table's number, or nothing at all), and every \ref to it will be silently wrong. Always: table/figure content, then \caption, then \label, in that order.

Math I — Core Environments

Both the Image Synthesis and Document Structure papers used cases for piecewise functions, and your teacher's templates independently exercise equation, align, cases, and bmatrix around a real worked quadratic-formula derivation. This section is the environments; §07 is the symbol vocabulary you'll fill them with.

Inline vs. display math, and the $$...$$ question

LaTeX distinguishes inline math (sits inside a line of running text, sized to match the surrounding text) from display math (broken onto its own centered line, typeset larger, used for anything you want the reader's eye to land on directly). Inline math is written between single dollar signs, $x^2$, or equivalently \(x^2\). Display math has more options than most students realize: bare \[ ... \] or the equation* environment both give you an unnumbered centered display; the equation environment gives you the same thing with an automatic number on the right. You will also see $$ ... $$ used for display math — your teacher's own template uses it directly, e.g. $$\alpha x^2 + bx + c = 0$$ — and it does work under plain LaTeX. It's worth knowing precisely why some style guides discourage it anyway: $$ is technically a plain-TeX construct that LaTeX merely tolerates for backward compatibility, and it doesn't integrate with amsmath's spacing and numbering logic as cleanly as \[...\] or equation* do — in rare cases it can produce inconsistent vertical spacing around the display. In practice, for coursework, either is accepted and both compile fine; just be consistent within one document, and know that equation/equation* are the only two of the three that can carry a \label for later reference.

Use \text{...} (not plain words typed directly into math mode) for the "if" labels — inside math mode, LaTeX treats every letter as a separate mathematical variable by default, italicizing each one and tightening the spacing between them as if you'd written a product of variables; typing if y \geq 0 without \text{} renders as a cramped, italic ifyge0-looking mess rather than readable words. \text{} is the escape hatch that says "this specific stretch is ordinary prose, format it like prose."

A frequent point of confusion: align is not the same environment as align*, and unlike equation/equation* the star has to be typed on both the \begin and \end lines — \begin{align*} ... \end{align*}, never a mix of one starred and one not.

A complete worked example: the quadratic formula

Your teacher's own template solves the general quadratic $\alpha x^2 + bx + c = 0$ using exactly the tools above chained together — display math for the setup, then align* for the two-root derivation. It's worth reading end-to-end as a template for "how do I actually write up a multi-step math solution":

source 
We want to write the solution for the
quadratic equation
$$\alpha x^2 + bx + c = 0$$.

The solution is
$$ x = \frac{1}{2\alpha} \times
   \left(-b + \sqrt{-b^2 \pm 4\cdot \alpha \cdot c}\right) $$

But there are two solutions actually.
\begin{align*}
 x_1 & = \frac{1}{2\alpha} \times
   \left(-b + \sqrt{-b^2 + 4\cdot \alpha \cdot c}\right)  \\
 x_2 & = \frac{1}{2\alpha} \times
   \left(-b - \sqrt{-b^2 - 4\cdot \alpha \cdot c}\right) \\
 & = \frac{-b - \sqrt{-b^2 - 4 \alpha c}}{2a}
\end{align*}
what to notice
The \left( ... \right) pair around the square root auto-sizes both parentheses to match the tall content between them — try deleting \left/\right and the parentheses stay small while the \sqrt{} grows past them.

The final line of the align* block has no left-hand side before its & — a genuinely empty alignment column is valid syntax, and lines up this continuation line's = directly under the one above it, the standard way to show "this simplifies further" across an extra line.
A bug hiding in plain sight: this real example from the course material writes \sqrt{-b^2 \pm 4\cdot \alpha \cdot c} in the general setup, but the two individual roots use + and - under the square root, not -b^2 + 4ac and -b^2 - 4ac — mathematically the standard discriminant is $b^2 - 4ac$, not $-b^2 \pm 4ac$. This is a genuine sign slip in the source document, not a LaTeX issue, and it's a good reminder that LaTeX will happily, perfectly typeset an equation that is mathematically wrong — compiling without errors is not the same thing as being correct, and proofreading the math itself is a separate job from proofreading the markup.

Math II — Symbols, Greek & Spacing

Pulled from Jim Hefferon's "LaTeX Math for Undergrads" cheat-sheet — this is the vocabulary layer that goes inside the environments from §06. Treat this section as a lookup reference, not something to memorize in one sitting.

Rule zero

Hefferon opens with the single rule that explains almost every beginner mistake in this whole area: any mathematics at all, even a lone variable, needs a math setting. Writing "the value of x is 7" directly produces exactly that ugly upright text; writing "the value of $x$ is $7$" produces properly italicized, correctly-spaced math. This is why a stray unmatched $ anywhere in your document throws off everything after it — LaTeX is a strict two-state machine (in math mode, or not), and every $ flips that state, so an odd number of them anywhere in the file leaves you in the wrong state for the rest of the document.

The Greek alphabet

Every Greek letter is \ followed by its lowercase spelled-out name for the lowercase glyph, and a capitalized command name for the uppercase glyph — but only for the letters whose uppercase form actually differs from a Latin letter (uppercase alpha looks identical to Latin "A," so LaTeX doesn't bother giving you a redundant \Alpha; you'd just type A). Several letters also have a "var" alternate glyph (e.g. \epsilon vs. \varepsilon) — both are mathematically the same letter, just different conventional glyph shapes, and which one a field prefers is mostly a matter of convention (physics tends to prefer the var-forms for epsilon and phi, for instance).

Fences that grow with their contents

Plain ( and ) always print at the same fixed size, which looks visibly wrong once the content between them grows tall — a fraction, a square root, a summation. \left( and \right) tell LaTeX to measure whatever sits between them and automatically scale both delimiters to match. The one strict rule: every \left must be matched by a corresponding \right somewhere later, and — a genuinely common source of a cryptic ! Missing \right error — both must end up on the same "line" of math as far as LaTeX's grouping is concerned, so splitting a \left(...\right) pair across two lines of an align block without care is a classic way to break a build.

Theorems & Proofs

Not covered anywhere in your four Online-1 papers, but a full worked example in your teacher's older template — this is likely to matter once your courses move past LaTeX mechanics into actually writing up algorithmic or mathematical arguments.

Defining your own theorem-like environments

amsthm doesn't ship with a "Theorem" environment ready to use out of the box — instead it gives you a factory, \newtheorem, for building exactly the environments your document needs, each with its own automatic numbering.

preamble (from your teacher's file) 
\usepackage{amsthm}

\newtheorem{theorem}{Theorem}
\newtheorem{lemma}[theorem]{Lemma}
what each argument means
First line: creates an environment named theorem, displayed with the label word "Theorem," and its own independent counter — \begin{theorem}...\end{theorem} will print "Theorem 1," then "Theorem 2," and so on.

Second line: creates lemma, displayed as "Lemma," but the [theorem] in square brackets means "share theorem's counter" instead of starting a fresh one. The two environments now interleave on one running number: Theorem 1, Lemma 2, Theorem 3 — never two "Lemma 1"s from two different environments looking like independent series.
The two optional arguments people mix up: \newtheorem{lemma}[theorem]{Lemma} and \newtheorem{lemma}{Lemma}[section] look almost identical but do genuinely different things, and this is one of the most commonly confused pairs in all of amsthm. The bracket immediately after the environment name ([theorem]) means "share this other environment's counter," producing interleaved numbering across two different environment types, as above. The bracket at the very end, after the display name ([section]) means "reset this environment's own counter every time the given sectioning unit increments," which instead produces numbers like "Lemma 2.1," "Lemma 2.2," then resetting to "Lemma 3.1" in the next section. They are not interchangeable, and using the wrong one produces numbering that looks superficially plausible but is structurally wrong.

Using it: a statement, then a proof

source (from your teacher's file) 
\begin{lemma}[Graph Representability]
    \label{lem:tree_representability}
    Every tree $T = (V, E)$ is a
    Pairwise Compatibility Graph (PCG).
\end{lemma}

\begin{proof}
    Let $T$ be a tree. By definition,
    there exists a non-negative edge
    weight assignment
    $w: E \rightarrow \mathbb{R}^+$
    and a real interval $[L, U]$ such
    that two vertices $u, v \in V$ are
    adjacent in the PCG if and only if
    the path distance $d_T(u,v)$ falls

\end{proof}

Lemma 1 (Graph Representability). Every tree T = (V, E) is a Pairwise Compatibility Graph (PCG).

Proof. Let T be a tree. By definition, there exists a non-negative edge weight assignment w: E → ℝ⁺ and a real interval [L, U] such that two vertices u, v ∈ V are adjacent in the PCG if and only if the path distance dT(u,v) falls within [L, U]. ∎

Two details worth internalizing. First, the square-bracket argument on \begin{lemma}[Graph Representability] is an optional title for this specific instance — it prints in parentheses right after the auto-generated number, exactly the same mechanism as a figure caption's own text, and it's entirely optional per-use, not something you declared back when you defined the environment. Second, \begin{proof}...\end{proof} is special-cased by amsthm: it automatically prefixes the block with the italicized word "Proof." and appends a small tombstone symbol (∎, the "Q.E.D. box") at the very end, entirely automatically — you never type either one yourself. If you want a different symbol, redefine it once in the preamble: \renewcommand{\qedsymbol}{$\blacksquare$}.

Changing the visual style

\theoremstyle{name}, called before the relevant \newtheorem calls (style changes only affect theorems defined afterward), switches between three built-in presentations: plain (bold header, italic body — the default, and what's used above), definition (bold header, upright/roman body — more common for definitions than for results being proven), and remark (italic header, upright body, usually with less vertical spacing — for asides and remarks that are less formally weighty than a theorem).

\theoremstyle{definition}
\newtheorem{definition}{Definition}

\theoremstyle{remark}
\newtheorem*{remark}{Remark}   % starred = unnumbered

A starred \newtheorem*{name}{Display Text} (note: the star goes on the definition, not on individual uses) creates an environment with no counter and no number at all — useful for a one-off "Remark" or "Note" that doesn't belong in a numbered sequence.

\url{} prints the raw address verbatim, in a monospace-like typewriter font, and — importantly — handles special characters like ~, _, and % inside the URL correctly, which would otherwise need manual escaping in ordinary LaTeX text (a bare % starts a comment; a bare _ tries to start a math subscript and errors outside math mode). This is precisely why it's the right choice inside a footnote or a reference list, where you want the exact address visible and copy-pasteable. \href{link}{text} hides the address behind readable words, appropriate for running prose where showing the raw URL would be visual clutter.

Load hyperref as the very last \usepackage — most conflicts trace back to something being loaded after it and clashing with the internal commands it redefines.

Citations & Building a .bib File from a PDF

Every paper you sent ended in a numbered reference like [1] Jean Meeus. Astronomical Algorithms... — that number is generated, never typed by hand. Here's the full pipeline: PDF → .bib entry → citation style.

Step 1 — pull the fields out of the source PDF

When you only have a PDF (not a DOI), extract these by hand from the cover/title page and copyright page:

FieldWhere to find it
Author(s)Title page — keep "Last, First" order, join multiple authors with and.
TitleTitle page, exact capitalization.
YearCopyright page ("©") or title page.
Publisher / JournalCopyright page (books) or the journal header/footer on each page (articles).
Volume, Number, PagesJournal articles only — usually in the running header/footer.
DOIFirst page or copyright page, format 10.xxxx/xxxxx.
Shortcut: if you have the title, search it on Google Scholar → click the quotation-mark "Cite" icon → "BibTeX" — it hands you a ready-made entry. If you have a DOI instead, paste it into doi2bib.org for the same result. Manual extraction (below) is your fallback when neither exists.

Step 2 — write the entry into references.bib

references.bib 
@book{meeus1991,
  author    = {Meeus, Jean},
  title     = {Astronomical Algorithms},
  publisher = {Willmann-Bell Inc.},
  year      = {1991}
}

@book{graham1994concrete,
  author    = {Graham, Ronald L. and Knuth, Donald E.
               and Patashnik, Oren},
  title     = {Concrete Mathematics: A Foundation
               for Computer Science},
  edition   = {2nd},
  publisher = {Addison-Wesley Longman},
  address   = {USA},
  year      = {1994}
}
entry types cheat-sheet
@article — author, title, journal, year, volume, number, pages

@inproceedings — author, title, booktitle, year, pages

@book — author/editor, title, publisher, year

@incollection — chapter inside an edited book

@misc — author, title, year, note/howpublished, url — for websites, GitHub repos, datasets

The word right after the opening brace (meeus1991) is the citation key — anything unique, no spaces. That's the string you'll type inside \cite{}.

Step 3a — numeric style, gives [1]

source 
% preamble
\bibliographystyle{plain}   % or ieeetr, unsrt, abbrv

% in text
As discussed by Meeus \cite{meeus1991}, ...

% at the very end of the document
\bibliography{references}
rendered
As discussed by Meeus [1], ...

Step 3b — author-year style, gives (Author, Year)

source 
% preamble
\usepackage{natbib}
\bibliographystyle{plainnat}   % or apalike

% in text
\citet{meeus1991} showed that ...      % textual
Leap years correct for drift \citep{meeus1991}.  % parenthetical
rendered
Meeus (1991) showed that ...
Leap years correct for drift (Meeus, 1991).

The same .bib file drives both formats — switching [1] ↔ (Author, Year) is purely a matter of which bibliography style you pick and whether you load natbib, never a matter of rewriting the .bib file.

Compile order matters: pdflatex → bibtex → pdflatex → pdflatex (four runs). Skipping steps is the #1 reason references show up as "[?]". Tools like latexmk -pdf automate this.

Step 3c — fine control: \bibpunct, \setcitestyle, \citestyle

These three all edit the same underlying punctuation settings, just at different levels of convenience. Think of them as one dial with three different grips:

CommandWhat it is
\bibpunct{...}The original, terse command — six positional arguments, no names. Powerful but easy to miscount.
\setcitestyle{...}A friendlier wrapper added in natbib v8.0 — same settings as \bibpunct, but as readable key=value pairs. Preferred for new documents.
\citestyle{name}Loads a whole preset of punctuation choices bundled under a given name (e.g. a journal's house style), without you specifying each piece yourself.

The low-level version: \bibpunct

source (preamble) 
% natbib's own built-in default:
\bibpunct[,]{(}{)}{;}{a}{,}{,}
argument-by-argument
[optional] punctuation before a post-note → ,
arg 1 opening bracket → (
arg 2 closing bracket → )
arg 3 separator between multiple keys in one \cite → ;
arg 4 mode: n=numeric, s=superscript, anything else (e.g. a)=author–year
arg 5 punctuation between author and year → ,
arg 6 punctuation between years sharing one author → ,

The readable version: \setcitestyle

source 
\usepackage{natbib}
\bibliographystyle{plainnat}
\setcitestyle{authoryear, open={((}, close={))}}

Leap years correct solar drift \citep{meeus1991}.
rendered
Leap years correct solar drift ((Meeus, 1991)).
KeyControls
authoryear / numbers / superOverall citation mode (arg 4 of \bibpunct).
round / square / open={c},close={c}Bracket shape (args 1–2). For curly { } or angle < > brackets, set open/close directly.
semicolon / comma / citesep={c}Separator between multiple citation keys in one \cite (arg 3).
aysep={c}Punctuation between author and year (arg 5).
yysep={c}Punctuation between years when the same author repeats (arg 6).
notesep={text}Text/punctuation inserted before a post-note.

The whole-preset version: \citestyle

source 
\usepackage{natbib}
\bibliographystyle{plainnat}
\citestyle{nature}   % pulls in Nature's own punctuation preset
what this buys you
\citestyle{name} loads the punctuation preset tied to a named house style (e.g. nature, agsm, dcu, kluwer, chicago) — independently of whatever \bibliographystyle is formatting your reference list.
Precedence to remember: calling \bibpunct, \setcitestyle, or \citestyle yourself always overrides — and silences — the automatic punctuation that some \bibliographystyle files try to set on their own. Since natbib v8.0, all three commands can also be issued anywhere in the document, so a thesis can legitimately switch citation style between chapters.

Loose Ends Worth Knowing

Small things that showed up once each across your papers and templates, and are easy to forget under exam pressure.

Footnotes

have applications in computer science
\footnote{\url{https://en.wikipedia.org/...}}

Place \footnote{} immediately after the word it annotates — numbering and page placement are automatic. Inside a footnote, prefer \url{} over \href{} for a raw address, since the reader can't click a printed page.

Block quotations

\begin{quote}
Don't forget to practice more problems!
\end{quote}

Indents both margins slightly — used for the closing remark in the Stirling Numbers paper. For a short quotation with no paragraph break, quotation (which also indents the first line of each paragraph) is the multi-paragraph sibling of quote.

Commenting out content

% this whole line is ignored
Visible text. % ignored from here on

A bare % makes LaTeX ignore everything after it on that line, including the line break — which is why two consecutive commented-out lines don't leave an accidental blank line/paragraph break in the output. This is exactly the mechanism your teacher's file uses to disable a whole figure block during drafting.

Two compiles minimum, always

Anything that depends on "what number will this be" — TOC/LOF/LOT, cross-references, theorem numbers — is wrong on the very first compile and correct by the second (or, for citations via BibTeX, correct only after the full four-run cycle in §10). Seeing a "?" or "??" in place of a number almost always means: compile again, don't start debugging the markup.
